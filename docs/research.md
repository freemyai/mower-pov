## 2. Rental Cat POV 的实际结构

作者描述的是 20 秒、1600×900、24 fps、480 帧、正式渲染 320 spp 的短片。程序生成房间、家具、水草、鱼、毛线球、猫爪与镜头运动；音轨并非全程序合成，而是两段标为 CC0 的实录加程序拟音。[R1, R9]

| 模块 | 已读取的实现 | 借鉴价值 | 不应照搬的部分 |
|---|---|---|---|
| 上游固定 | `integration/upstream.json` 锁提交与每文件 SHA-256；`tools/build.py` 下载、缓存、校验 | 依赖可追溯、网络失败可重试、拒绝漂移 | 该外部渲染器的授权不是本仓库 MIT 授权 |
| 集成机制 | JSON 记录字符偏移、删除长度、插入文本；构建时逆序应用 | 在固定版本上快速制作独立场景 | 不是稳定插件 API；校验避免错版本，但并不让升级维护自动变容易 |
| 镜头 | `scene/film-motion.h` 使用时间标记插值，额外叠加步态与休息动作 | 在少量事件中形成连续、可复现的镜头 | 猫的视线、步态、跳跃、闭眼不适用于固定机载相机 |
| 动作反应 | `escapePosition` 编排两条鱼的逃离轨迹和不同启动延迟 | 细小的因果事件比增加大量杂物更有效 | 是脚本动画，不是证明物理仿真或感知闭环 |
| 预览和成片 | 640×360、8 spp 预览；1600×900、320 spp 正式流程 | 先看动作、后花预算渲染 | 时长、分辨率、帧数写死，不是通用任务系统 |
| 断点恢复 | 根据原始 PPM 是否存在以及固定字节数判断缺帧 | 避免中断后全部重做 | 无场景/相机/配置指纹；同尺寸旧帧可能被误当作新结果 |
| 降噪 | 固定 1600×900；RGB 输入 OIDN RT；后续 FFmpeg 使用 hqdn3d | 把降噪和编码作为独立阶段 | 不能据此保证运动草叶的时域稳定；本项目要保留原始层与对照样片 |
| 声音 | `audio/mix.py` 中直接写入若干时间点；CC0 实录与拟音混合 | 短片声音设计清晰，来源明确 | 变更运动路线后时间点可能失配，应改为共享作业事件 |

这些结论来自代码静态审阅。[R2–R10] “可能误用旧帧”“路线修改可能失配”是依据代码结构提出的工程风险，不是声称原作者成片已经发生这些故障。

## 3. 三个参考项目各取什么

**Rental Cat POV：**借鉴固定依赖、分层文件、明确事件、预览到正式的流程，而不是复制猫的镜头和鱼缸。

**Robot Vacuum POV：**作者实现了按加速度约束积分的机器人运动、机身固定相机、地毯/地板事件及声音时间线；文档指出只有玩具恐龙会响应，谷物与灰尘不会被清走。这提醒我们：行驶视频不自动等于作业视频。[R11]

**Cat Garden：**借鉴程序化草叶、近地尺度、植物透光、连续风场，以及按整个已知路线分配细节、避免运行时 LOD 突变。作者文档也表明，掠射角下大量草叶的遍历是重要开销，且简单“异常帧分数”会误报正常的近景运动。[R12]

## 4. 必须单独处理的授权问题

Rental Cat POV 的 README 和 CREDITS 说明：MIT 覆盖其新增原创代码；构建时获取的 Cat Garden 渲染器采用独立授权，所锁定版本未标注开源许可。读取固定版本根目录也没有发现根目录 LICENSE 文件。[R1, R9]

GitHub 官方说明：公开可见与获得开放使用、修改、分发许可不是一回事；平台允许查看/fork，也不等于任意再授权。[R13]

因此，本方案不把 Cat Garden 代码直接打包到 freemyai 新仓库，不把运行时下载当作授权问题的解决办法，也不把改写变量名或让模型转译代码当作独立实现。可采用的路径是：取得明确授权，或只借鉴通用思路并独立实现，或换用授权明确的成熟渲染器。

## 5. 推荐路线与备选

| 路线 | 适用条件 | 代价 | 本方案位置 |
|---|---|---|---|
| 独立 Python 作业核心 + Blender/Cycles | 主要目标是高质量机载视频与可复现开源 | 需要遵循 Blender Python API 发布许可，验证草叶几何与性能 | 首版主路线 |
| 自研 C++/Metal 渲染器 | 必须展示“自写渲染器”，且主要运行在 Apple Silicon | 渲染、BVH、材质、滤波、平台适配均需维护；上游授权另行解决 | 首版不并行实现 |
| 完整机器人仿真系统再接视觉渲染 | 要验证导航、感知或训练策略 | 项目范围明显扩大 | v0.2 以后单独立项 |

选择成熟后端是本方案建议，不是声称用户已经选择或禁止自研。场景、作业状态、相机和声音仍由代码生成；README 必须准确写明使用 Blender/Cycles，不能宣传成“没有使用任何现成渲染器”。

候选基线锁定 Blender 5.2.4 LTS。官方发布页记载 5.2.4 发布于 2026-11-10，5.2 LTS 支持到 2028 年 7 月。选择它是为了固定可维护基线，不是宣称它是最新主版本。[R14] Cycles 官方文档列出 CUDA/OptiX、HIP、oneAPI、Metal 等后端；具体设备仍要经过本机探测与烟雾测试。[R15–R16]

## 6. 开源定位

建议单独建立 `freemyai/mower-pov`，保留 `freemyai/website` 作为作品展示入口。官网现有 `data/gallery.json`、`assets/media/`、来源与验证字段、分享别名流程，已经能承载这类作品；不必把渲染器塞进网站，也不必先做一个昂贵的浏览器实时引擎。[R20]

Blender 官方 FAQ 对使用其 Python API 的公开脚本有 GPL 要求，同时区分软件许可与渲染产物。因此首版建议代码统一采用 GPL-3.0-or-later，成片和原创素材另行明确许可；任何第三方素材继续遵守其原许可。以后若把完全独立、经文件/子进程接口通信的作业核心抽出，再单独评估更宽松的许可，避免首版制造混合许可歧义。[R18]
