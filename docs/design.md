# Freemy Mower POV 技术设计

日期：2026-11-20。状态：待执行的设计建议，尚未生成视频或创建远端仓库。

## 1. 目标与非目标

目标是让 Codex 编写并运行一个可复现的程序，生成割草机器人固定机载相机看到的作业视频：真实尺度的草坪、可信的轮式运动、真正保留的割草状态、同步声音，以及可检查的渲染证据。拟发布仓库为 `freemyai/mower-pov`。

首版交付 40 秒、1920×1080、30 fps、1200 帧的一镜到底视频，另交 8 秒关键样片、关键帧联系表、运行配置、状态缓存、质量报告和源码。

首版不是自主导航算法，不是农业切割物理验证，也不是已经验证可迁移到实机的训练数据集。固定作业路线可以是脚本，但它必须驱动作业状态，不能只移动相机。暂不做 SLAM、强化学习、草茎断裂力学、全景城市、多人互动、实时网页渲染、双渲染后端或云端付费渲染服务。

默认允许成熟渲染器，但场景和运动由代码构建；默认不需要外购模型、HDRI、视频或音效。此处是设计假设，不是新增用户硬性限制。

## 2. 方案选择

采用独立 Python 核心计算地形、运动、切割与事件；缓存后由 Blender/Cycles 只读重放；音频和质量检查也读取相同缓存。主线只实现 Blender 后端，不同时编写 Metal 引擎。

备选路线、授权原因与参考项目事实见 `RESEARCH.md`。硬件未提供，必须先实测设备。候选工具基线为 Blender 5.2.4 LTS、外部 Python 3.11+、NumPy、pytest、FFmpeg/ffprobe；执行阶段锁定具体依赖与平台安装包校验值。外部 Python 负责配置与仿真；Blender 内置 Python 只读取标准 JSON/NPZ，不把外部虚拟环境的包目录强塞进 Blender。

## 3. 画面与节奏

场景为约 12×10 米的小庭院：轻微地形起伏、树影、花坛边界、少量自然细节。首版只建镜头需要的空间，不以远景房屋和装饰物数量作为质量指标。

| 时间 | 目标镜头 | 必须看到或听到的证据 |
|---|---|---|
| 0–3 秒 | 树荫下待机并启动 | 固定机位、少量机壳、启动声音与状态一致 |
| 3–16 秒 | 第一条直线作业 | 草叶尺度、地形引起的轻微俯仰、连续行进 |
| 16–22 秒 | 边界前减速并掉头 | 转向受速度/角速度约束，机身不穿越花坛 |
| 22–35 秒 | 相邻作业行前进 | 侧前方能辨认上一趟短草与尚未切割的长草 |
| 35–40 秒 | 继续作业、轻微减速收尾 | 草带与轮迹仍然存在，音画同步 |

这些时间是镜头预算。先用满足约束的轨迹计算实际持续时间，再调整路线长度以保持 40 秒；不能为了卡秒而瞬移或突然改变速度。

核心构图约束：前向机载相机通常看不到刀盘下方。要通过掉头后的旧草带证明作业效果，不能让机器前方的草提前消失。如果真实宽度的草带从该机位不易辨认，优先调整掉头位置、光向、相机安装角或返程构图，不偷改刀盘宽度，也不让草带只变色。

## 5. 数据流与职责边界

```text
配置、种子、版本与素材清单
           │
           ▼
地形与作业路线 → 运动积分 → 刀盘扫掠与轮迹 → 共享事件
           │                     │
           └────── 不可变作业缓存 ─┘
                             │
          ┌──────────────────┼─────────────────┐
          ▼                  ▼                 ▼
程序化三维场景与机载相机    音频生成          状态/碰撞测试
          │                  │
          ▼                  │
分帧渲染 → 降噪 → 色彩处理 ───┴→ 编码 → 质量审查 → Release
```

渲染器不重新决定哪里被割过；声音程序不另写一套路线；质量检查不能通过另一套不同定义的坐标去猜测结果。

### 坐标和时间

全局与机身采用右手坐标；全局 Z 向上，机身 X 向前、Y 向左、Z 向上。机身原点定义为底盘参考接地平面的中心；平地时原点高度为零，几何外壳和相机用固定安装偏移定义。

对外相机光学坐标为 X 向右、Y 向下、Z 向前。Blender 相机适配器负责到其本地相机坐标的转换，不允许在不同模块隐式翻转轴。

`T_world_camera(t) = T_world_body(t) @ T_body_camera`。安装外参不随时间改变。地形和底盘微振动先作用于机身，再带动相机。

逻辑视频帧编号为 0…1199，中心时间 `t = frame / 30`；Blender 内部帧编号可以不同，但适配器必须显式转换。所有动画、音频事件、风和草状态使用绝对秒数，不使用“本次分段从零开始”的局部时间。

### 缓存约定

`trajectory.npz`：时间、位置、连续航向、姿态、线速度、角速度、轮速、刀盘开关。

`terrain.npz`：高度场、坐标原点、间距与可割区域掩码。

`grass_state.npz`：原始草高、首次割到时间、轮压方向与事件数据。永未割到的时间可在二进制数组中使用正无穷；对外 JSON 必须用有效标志/null，不输出非标准 Infinity。

`events.json`：时间、事件类型、位置、强度、关联状态；包括启动、刀盘开关、进入高负载区、地形冲击、停止等。

`manifest.json`：模式版本、代码提交、配置摘要、种子、资产哈希、工具版本、GPU/驱动、渲染预设、全部缓存哈希。

## 6. 运动和机载相机

核心采用差速轮式运动模型，固定 240 Hz 积分，限制线速度、角速度及其变化率。路线不是直接给相机打关键帧，而是生成控制量并积分机器人位姿。航向连续展开，避免 ±π 附近翻转。

从轮接触采样点拟合支撑平面，再用有阻尼的姿态响应产生俯仰与侧倾。残余电机振动采用低幅值、带限信号，受速度/刀盘状态驱动，不逐帧独立随机抖动。该模型是视觉近似，不宣称复现真实轮地接触动力学。

碰撞验证检查整个机身的连续扫掠区域；刀盘可割区域、机身可通行区域与轮轨分开定义。首版可用保守包围体检查，转弯不能只验证离散路径点。前向相机保持固定，不因为发现草带而自行转头。

## 7. 持久割草状态

### 7.1 第一版状态模型

固定切割高度、无再生长的首版使用首次切割时间场。定义 `t_cut(x,y)` 为：刀盘开启且有效切割区域第一次覆盖该位置的时刻。未覆盖则为正无穷。

对于草根 i：

```text
height_i(t) = h0_i                         当 t < t_cut_i
height_i(t) = min(h0_i, configured_height) 当 t >= t_cut_i
```

轮胎压弯另存状态，只改变倾斜/弯曲，不永久改变草长。碎草是切割事件的可选装饰，不反过来定义是否完成割草。

该首次切割模型仅适用于首版固定割高。未来支持可变割高、重复修剪或生长时，应改为事件历史/最小高度更新，不能继续把单张时间图当万能状态。

### 7.2 几何覆盖必须正确

刀盘中心由机身位姿与刀盘安装位置计算，不得用相机位置替代。每个有效积分区间对刀盘圆盘的连续运动做扫掠；平面上可用线段胶囊覆盖，转弯按误差约束细分。求首次进入时间，而不是只在 30 fps 帧位置盖圆。刀盘关闭时不修改状态。

默认 1 cm 网格用于宽相检测、缓存和可视化。边界草根应使用细化的扫掠查询，或明确测量网格误差。禁止直接对含无穷值的时间纹理做线性插值；禁止为了软边把未来状态混入当前帧。

约 12×10 m、1 cm 网格包含 120 万格；单张 float32 图约 4.8 MB（十进制，不含元数据）。状态图本身不需要为每帧存整张草坪，但植物几何可能消耗更多内存，必须单独测量。

### 7.3 确定性与重渲染

仿真先完成，再渲染。随机抽取第 900 帧、顺序渲染到第 900 帧、恢复中断后渲染第 900 帧，读取相同的状态。未实际实现前，不应承诺不同 GPU 的浮点像素逐位一致；状态一致、同栈重放一致与跨平台视觉容差分别测试。

### 7.4 露馅风险

草高要真实改变几何，而不只是颜色。切后草根的位置、颜色身份及密度应保持，不能换一张“短草纹理”导致位置整体跳动。切割发生在机壳遮挡区域，尽量避免前向镜头看到不合理的缩放动画。

## 8. 程序化草坪与场景

采用固定草根 ID 与空间哈希生成稳定属性：根位置、原始长度、宽度、弯曲、朝向、色差、枯尖。风使用空间连续的风场及每株固定相位。禁止每帧重抽草位置。

近处使用可见轮廓的三维草叶；中景用多原型实例；远景减少几何并用低频材质补充。首版按整条相机路径的可见区域并集预分配细节，加入风摆、阴影与反射所需裕量，避免随相机距离实时切换产生跳变。不是简单用“相机路径附近”替代所有可见/投影区域。

Blender 侧采用 Geometry Nodes 或等价的程序化批量几何，存储根 ID、h0、t_cut 等属性。优先保持草叶拓扑稳定，让草长与弯曲在时间上可求值；不能每帧从 Python 重建整个庭院。动作模糊需要验证子帧求值，而不只是整数帧看起来正确。

地形、树影、花坛、土壤和少量枯叶分层生成。草叶背光透射与根部遮蔽比远景豪宅更优先。不要用大量镜头光晕、强胶片颗粒或过饱和绿色掩盖材质问题。

## 9. 渲染、降噪和缓存

### 9.1 三级预设

| 预设 | 建议起点 | 用途 |
|---|---|---|
| smoke | 640×360、8 spp、少量指定帧 | 检查依赖、相机、语法和基本输出 |
| preview | 960×540、32 spp、30 fps | 轨迹、时序、作业痕迹和动作检查 |
| final | 1920×1080、128–256 spp 候选 | 通过基准和关键样片后确定正式配置 |

采样值是待实测初值，不是质量保证；不同引擎的 spp 不能直接用来换算画质和时间。基准应包括密草掠射角、转弯、树影和远景，记录中位数/高分位帧耗时、峰值内存、同步/BVH/降噪开销、每帧磁盘大小。不要拿一张简单帧预测整片。

### 9.2 管线

保留线性 EXR 或等价高精度中间结果，包含 beauty、albedo、normal；验证后再决定是否增加 depth、motion 等层。先降噪，再明确执行显示变换与 Rec.709 SDR 输出转换，最终编码 H.264/yuv420p、AAC、faststart。不要仅写色彩标签而不做正确转换。

参考项目的 OIDN 用法是逐帧 RGB 滤波。本项目先验证带 albedo/normal 辅助层的空间降噪，再以连续样片检查闪烁；不把“接上 OIDN”写成“已经完成时域稳定”。遇到细草丢失或拖影，先分析采样、几何和滤波，不用大模糊抹平一切。

快门初值 180°，先关掉额外滚动快门和强畸变。启用自动曝光时先生成全片曝光曲线并缓存，或保存完整状态检查点；分段不能各自重新适应曝光。

### 9.3 恢复与失效

以代码/配置/场景/轨迹/状态/版本/色彩处理的哈希建立运行目录。允许每 150 帧一个任务片段，但帧时间始终全局一致。每帧先写临时文件，校验后原子重命名，登记完成记录。只验证字节大小不足以保证缓存有效。

更改相机、草高、割高、种子、天气、几何或采样时，相关缓存必须失效。一个运行目录不得混用两种配置的帧。涉及时间滤波时，要处理分段重叠区/历史状态；没有实现就禁用该滤波，而不是产生接缝。

## 10. 声音

首版使用程序合成：行走电机、刀盘、草接触、风与远处环境底噪；不必引入猫叫或猫脚步。电机声随真实速度与转向变化，刀盘声跟随开关，负载由单位时间新去除草量的近似决定，不能每次经过已割草都播放同样的“重负载”。

音轨从 events 和 trajectory 生成，长度为 1,920,000 个 48 kHz 双声道采样帧。保持足够峰值余量，检查削波、突变和事件同步。频谱和响度检查不能代替试听；没有试听条件时报告必须写“未试听”，发布验收由人工确认声音。

## 11. 验收标准

### 状态与运动的硬门槛

割草只发生在刀盘开启时的有效扫掠区域；刀盘关闭、路径外区域不变；重复经过不使草重新变长；草高不高于初始值。1 cm 网格原型的覆盖边界误差目标不超过 2 cm，正式值通过解析直线路径和收敛实验确定。

相机外参保持不变；连续航向无 2π 跳跃；速度/加速度在配置上限内；机身不穿越固定障碍边界。不同渲染顺序得到相同作业状态。更改配置后不得复用旧指纹帧。

### 视频与声音的硬门槛

40 秒、1200 个视频帧、1920×1080、30 fps；全片能完整解码。音视频事件误差目标在一帧以内；允许编码器正常首尾延迟，但不可掩盖实际错位。检查空文件、缺帧、异常尺寸、错误色彩标记与音轨削波。

### 视觉与听觉的人审门槛

8 秒关键样片中必须包含掉头后旧草带的可见证据。没有明显提前割草、草根瞬移、轮地漂浮、机壳穿透、草叶成片消失、转弯视角跳动、分段曝光断裂。对黑帧/冻结帧/异常变化检测只生成候选，结合停机、阴影和真实近景运动审查，不把一个分数当最终结论。

至少检查近景草、阴影草、远景草、转弯边界、短草带五类区域；输出原始/降噪对照和联系表。没有实际看图或试听的检查项不得写“通过”。

## 12. 发布边界与后续扩展

代码建议 GPL-3.0-or-later；成片、文档、原创素材另列许可；保留参考致谢和任何实际复用文件的原始许可。依赖与素材清单必须区分“灵感”“实际依赖”“代码复用”。

公开仓库放源码、小型预览、测试与复现文档；MP4、状态样例与完整报告放 Release；大体积中间帧不进 Git。普通 CI 使用托管 CPU runner 做单元测试和少量低分辨率渲染。首版 GPU 正式渲染在本地或隔离的受控流程运行，不让公共 fork 的 PR 在私人 GPU 自托管机器执行。

README 明示“固定路线的视觉仿真”“使用 Blender/Cycles”“由 Codex 辅助开发”，记录实际使用的模型标识和日期，不虚构一条提示词一次成功。保持无需 AI API 密钥也能重渲染。

官网接入单独提交：真实成片抽帧、来源、许可证、已验证设备/音频/播放情况、短预览与 Release 链接。读取实际 gallery schema 后再添加记录，不凭 README 猜字段。延续现有分享别名流程与测试命令，不顺手改站点架构。
